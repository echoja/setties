# 규칙 문서 작성

현재 사용자 지시와 프로젝트 규칙을 우선한다. 기존 규칙의 언어와 적용 범위를 유지하고, 새 규칙 본문은 별도 언어 지시가 없으면 한국어로 작성한다.

- 익숙한 용어 사용. 업계에서 통용되지 않는 약어는 해당 문서나 관련 용어집에서 먼저 설명.
- 제목, 목록, 코드, 링크를 중심으로 구성. 의미 전달에 필요하지 않은 강조와 장식은 생략.
- 적용 조건과 범위를 구체적으로 명시. 강한 표현은 실제로 예외가 없는 제약에 사용하며, 기존의 필수 요구를 문체만을 위해 완화하지 않음.
- 규칙 자체를 짧게 작성. 판단에 필요한 근거는 1문장까지 덧붙이고, 짧은 예시와 용어 설명은 필요한 곳에 배치.
- 사용자가 요청한 규칙 변경은 해당 도구와 범위의 정본에 직접 반영. 전역 규칙은 Setties의 `.codex/AGENTS.md`, 작업별 절차는 해당 스킬이나 프로젝트 규칙에서 관리.
- 명시적인 규칙 수정 요청과 기억 요청을 반영. 일상적인 발언을 전역 규칙으로 확대하지 않으며, Basana 노트의 능동 관리 범위는 기존 지시를 따름.

문장으로 적어야 조건과 행동이 명확해지는 규칙은 완성된 문장으로 쓴다. 규칙 문서의 형식을 맞추기 위해 필수 링크나 검증 근거를 제거하지 않는다.
