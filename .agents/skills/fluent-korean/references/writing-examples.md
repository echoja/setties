# 산출물 문서 글쓰기 스타일 예시

[산출물 글쓰기 스타일](personal-writing-style.md)을 적용하는 예시다. 현재 사용자 지시와 프로젝트 규칙을 우선하며, 예시 속 파일 위치 생략이나 목록 사용을 다른 문서에 기계적으로 적용하지 않는다. 인용과 코드 자체는 보존한다.

-  `라이브로 확인했다` → `브라우저로 확인했다`

## 1. 일반 설명에서 불필요한 줄 번호 생략

- `ApiController.cs:146-147` 에서 스트리밍 → 프록시에서 스트리밍
- `Startup.cs:232` 우회 → 모니터링 미들웨어에서 우회

## 2. 코드 위치 대신 동작 설명

- `BackendServiceClient.SendAsync` 가 raw 패스스루 → raw 패스스루 경로가 있음
- `isFileDownload` 판정 → 파일 다운로드 판정
- `ForwardToBackendAsync` 가 헤더만 받음 → 포워딩 시 헤더만 받음
- 유지 대상: `HttpClient`, `ResponseHeadersRead`, `IStreamWriterAsync` 는 프레임워크와 서드파티 공개명이라 그대로 쓴다.

## 3. 쓸모없는 메타 정보 안 넣기

- `## 3. 조치 내용 (이번 브랜치에서 반영)` → `## 3. 조치 내용`
- `커밋 65abf6b 기준` → 삭제
- `작성자: 홍길동, 리뷰 대기` 같은 문서 상태 → 본문에서 제거

## 4. 중의적 용어 대신 직설적으로

- `버퍼링` → `메모리에 전부 로드`
- `이슈` → `버그`, `제약`, `질문` (무엇인지 명시)
- `최적화했음` → `N+1 쿼리 제거` 같은 구체 동작
- `핸들링` → `처리` 또는 구체 동작
- `레거시` (단독) → `구세대 API(신규 코드 비권장)`
- `~에 존재` → `~에 있다`; `존재하지 않음` → `없음`

## 5. 비유와 은유 대신 직접적 기술 용어

- `다시 굽는 과정` → `다시 직렬화하는 과정`
- `통을 가득 채운 뒤 건넨다` → `응답 전체를 메모리에 모은 뒤 반환`
- `터진다` → `OOME 발생` 또는 `크래시`
- `뺑뺑이 돈다` → `무한 로딩` 또는 `무한 재시도`
- `싹 갈아엎는다` → `전면 재작성`

## 6. 뭉뚱그리는 용어 대신 정확한 대상명

- `typed 클라이언트` → `JsonHttpClient` 와 `JsonApiClient`(특정) 또는 `ServiceStack 클라이언트`(일반)
- `백엔드` → `API 서버` 와 `프론트엔드 서버` 로 구분
- `서버가 죽음` → `웹 서버 pod 가 OOME`
- `클라이언트` → `브라우저(프론트)` 와 `프론트엔드 서버` 로 구분

## 7. 간결하게, 대시 부연 축소

- `공통 — 버전 간 동일` → `모두 동일`
- `가능하나 — 단, ...` → 문장 분리
- 삽입구 중첩 남발 → 핵심만 남기고 분리

## 8. 주장 대신 근거, 조사 방법론은 앞세우지 않기

- `어떤 버전도 스트리밍 인자 없음` → 실제 send 시그니처 목록 첨부
- 서두에 `(디컴파일로 확인)` → 결론을 공식 문서 링크에 앵커링, 방법론은 뒤로
- `내가 해보니 안 되던데` → 재현 조건과 관측 결과

## 9. 산문 구분자로 빗금, 가운데점, 더하기 안 쓰기

- `로드/로깅` → `로드와 로깅` 또는 `로드, 로깅`
- `Alice · Bob` → `Alice 와 Bob` 또는 `Alice, Bob`
- `핸들러·커넥션 풀` → `핸들러와 커넥션 풀`
- `로드 + 로깅` → `로드 및 로깅`
- `net6.0 + netstandard2.0` → `net6.0 및 netstandard2.0`
- 예외(그대로 둠): 경로 `Web/AdminWeb`, 버전 `5.11/6.11`, 코드 `Get<Stream>`

## 10. 단어의 윤곽과 크기 검토

- `본문` → `body` (본문은 뜻이 너무 넓어 크기가 큼. body 는 HTTP body 를 뚜렷이 가리킴)
- `생산` → `응답을 보냄`, `소비` → `응답을 받음` (생산, 소비는 너무 추상적)
- 단어 고를 때 두 가지 검토: 한국인 개발자에게 윤곽이 뚜렷한가, 너무 추상적이거나 구체적이지 않은가

## 11. 관계는 서술어로 끝내기

- `각 버전 동작 기준` → `각 버전에 따라 다름`
- `성능 측면 고려` → `성능이 나빠질 수 있음`
- 관계의 자리만 가리키고 내용은 비운 명사구(`~기준`, `~측면`, `~차원`, `~부분`, `~관련`)로 끝내지 말 것

## 12. 빈 도입 문장 지우기

- `35열 고정이다.` + 1~35 열 표 → 표만 남김 (열 수는 표가 말함)
- `읽는 규칙이다.` + 규칙 목록 → 목록만 남김
- `동작은 이렇다.` → 앞 문장에 붙이거나 삭제
- `탭은 세 개다.` + 탭 3개 목록 → 목록만 남김
- `모달에 담는 것이다.` → `버튼을 누르면 확인 모달을 먼저 띄우고 다음을 담는다.`
- 남기는 경우: `반드시 두는 칸이 둘이다` → `다음 두 칸은 반드시 둔다` (개수 대신 규범을 담음)
- 남기는 경우: 한 절에서 목록 두 개를 가르는 라벨 구실을 할 때 (`화면 변경은 셋이다`, `버튼 구성이다`)

## 13. 반복되는 동작은 술어명사로 고정

- `벌크 등록 페이지를 새로 만든다` → `벌크 등록 페이지 신규 생성`
- `다중 등록 모달과 다중 수정 모달을 없앤다` → `다중 등록 모달과 다중 수정 모달 제거`
- `행별 편집과 행별 삭제는 그대로 둔다` → `행별 편집과 행별 삭제 유지`
- 시스템에 이름이 있으면 거기 맞춤: requestType 의 `add`, `modify` → 화면에서도 `신규 생성`, `수정`
- 문장으로 두는 경우: 동작 규칙과 근거 (`열 수가 35가 아닌 행이 하나라도 있으면 아무것도 등록하지 않는다`)
- 명사화 남용 경계: `검토 진행`, `반영 필요`, `확인 요망` 은 주어가 사라져 책임이 흐려짐

## 14. 목록은 같은 성격끼리, 결론은 목록 밖으로

- 필요 조건 둘과 결론 하나를 한 목록에 나열 → 조건만 목록으로 두고 결론은 목록 뒤 문장으로
- 사실 셋과 대응책 하나를 한 목록에 나열 → 사실만 목록으로 두고 대응책은 뒤 문장으로
- 스펙 나열은 라벨을 붙여 형태를 맞춤: `제공 위치:`, `구성:`, `인코딩:`, `생성 방식:`
- 근거 나열도 축을 붙여 맞춤: `모델:`, `실데이터:`, `비용:`

## 15. 목록은 명사형, 문단은 평서형

- `- 셀 하나를 복사해 그 언어 칸에 붙여넣는다. 언어가 30개면 30번 반복한다.` → `- 셀 하나를 복사해 그 언어 칸에 붙여넣음(언어가 30개면 30번 반복)`
- `- 전체 일괄 버튼은 두지 않는다.` → `- 전체 일괄 버튼 없음`
- `- 진행 상태는 전송 중일 때만 한 줄로 보여준다.` → `- 진행 상태: 전송 중일 때만 한 줄로 표시`
- 문단은 그대로 평서형: `오류를 파일 수준과 행 수준으로 나누는 근거는 복구 비용이다.`
- 이유: 목록에서는 주어가 뻔해 군더더기만 늘고, 문단에서는 인과가 두세 절로 이어져 `~하므로 ~함` 이 겹치면 읽기 어려움

## 16. 이름과 설명은 쌍점으로, 줄표는 안 씀

- `- 자동 재시도 끄기 — 현재 설정은 재시도 3회` → `- 자동 재시도 끄기: 현재 설정은 재시도 3회`
- `- 레이트리밋 초과는 실패로 기록하지 않는다. 이 차단은 …` → `- rate limit 초과: 실패로 기록하지 않음. 요청이 핸들러에 닿기 전에 차단되어 …`
- `- 여러 항목을 한 번에 받는 백엔드 엔드포인트 요구. 전송 계층으로 흡수하고 나중에 판단한다.` → `- 벌크 엔드포인트 요구: 전송 계층으로 흡수하고 나중에 판단`

## 17. 라벨형 도입과 단일 컬럼 표

- `버튼 구성이다.` → `버튼 구성:`
- `페이지 자리는 아래와 같다.` → `페이지 자리:`
- `여기서 세 가지가 따라온다.` → `여기서 따라오는 문제:`
- 문단으로 두는 경우: 도입이 사실이나 결정을 담을 때 (`실패를 두 갈래로 가른다.`, `오류를 파일 수준과 행 수준으로 나누는 근거는 복구 비용이다.`)
- 열이 하나뿐인 표(`| 사유 |` 한 열) → `사유:` 라벨 + 목록

## 18. 비교 가능한 정보를 목록으로 구성

- `단일 금액 입력이다. 사이트 분기가 없다. 최소값 1, 자릿수 9 제한이고 상한은 없다.` →

    ```
    - 입력: 단일 금액
    - 사이트 분기 없음
    - 최소값: 1
    - 최대값: 없음
    - 자릿수 제한: 9자리
    ```

## 19. 배포 동시성 표현

- `같은 배포 창에 함께 나가야 한다` → `함께 배포되어야 한다`
- `이 PR 만 먼저 나가면` → `이 PR 만 먼저 배포되면`
